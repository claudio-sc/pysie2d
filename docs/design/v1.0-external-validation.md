# v1.0 — external validation for non-circular shapes

**Status: scoping.** This is the high-level spec. It fixes the goal, the
comparison contract, the two anchors and the milestone boundaries. Code-specs
for each milestone come later and separately.

## 1. Why

Every validation anchor in the repo is circular. `reference/mie.py` and the
analytic Mie resonances validate the solver at `m = 0`; for a Gielis star with
`m ≠ 0` nothing independent has ever been checked. Non-negotiable §3 says new
physics needs an anchor that does not share our assumptions, and agreement
between `assemble_matrix` and `assemble_matrix_reference` is not one: they
share the formulation, the parametrisation and the quadrature.

The claim to be supported is narrow and worth stating exactly:

> For a smooth non-circular boundary, pysie2d's driven observables agree with
> an independent Maxwell solver to within that solver's own convergence floor.

Nothing about eigenvalues, and nothing about convergence *rate* — only that the
converged numbers are the same numbers.

## 2. Comparison contract

Fixed here so that a later disagreement is about physics, not bookkeeping.

- **Absolute cross-sections, not efficiencies.** `C_sca`, `C_ext`, `C_abs` in
  nm (a 2-D cross-section is a length). The `Q_*` normalisation by `2·rad` is
  documented as approximate for non-circular shapes and would inject an
  arbitrary reference length into the comparison; sidestep it entirely.
  pysie2d produces these as `Q_* · 2·rad` — the validation script does that
  multiplication, no API change is proposed.
- **Spectra, not resonance parameters.** `C(λ)` on a shared wavelength grid,
  compared pointwise. No Lorentzian fit, no extracted λ or Q. That comparison
  is a separate, later milestone and it is not part of v1.0.
- **Both polarisations.** `pol = 2` (TE, `E_y`) and `pol = 1` (TM, `H_y`) —
  conventions §2. Mapping our `pol` onto each external tool's polarisation
  naming is a per-tool gate, checked on the circle before the star is run.
- **Non-dispersive material, lossless and lossy.** A real `n_core` exercises
  `C_abs = 0` as a null test; a complex one exercises the absorption path.
- **Vacuum wavelengths in, always** (conventions §2). Any external tool
  configured in frequency or in background wavelength converts at exactly one
  place in the validation script.

## 3. Two anchors, split by regime

Neither tool is asked to do the regime it is bad at.

| | MEEP | FEniCSx / dolfinx |
|---|---|---|
| Method | FDTD, time domain | FEM, frequency domain |
| Regime | broad, low-Q resonance | sharp, higher-Q resonances |
| Cost shape | one broadband run per geometry | one solve per wavelength |
| Independence | maximal — shares no linear algebra with us | volume formulation, PML, curved elements |

**MEEP** is the most independent check available: nothing in a time-stepped
Yee grid resembles a boundary integral. It is also the one that degrades with
Q, because a long-lived resonance must be run until it rings down and the PML
must not reflect at the level of the residual field. So it takes the broad
resonance.

**dolfinx** takes the sharp ones. Its demonstration case is 2-D scattering from
a cylinder with PML computing absorption, scattering and extinction, validated
against analytic Mie — the same observables and the same anchor the repo
already uses, which makes gate 1 below nearly free. The boundary is meshed with
gmsh, so a Gielis contour enters as a curve, and high-order elements keep the
geometry error below the field error.

MEEP was used on a *different* package previously; nothing is reusable here,
and the MEEP milestone is built from scratch.

**One overlap wavelength band is run by both**, in a regime each handles, so
the two externals are also checked against each other. Without it the two
milestones never touch and a tool-specific error stays invisible.

## 4. Observables, in order

1. **Cross-sections.** `C_sca`, `C_ext`, `C_abs` vs λ. Complete deliverable on
   its own.
2. **LDOS / near field.** Second milestone, and the harder half:
   - MEEP computes LDOS natively, normalised against the same source in
     vacuum. Reconciling that with `relative_ldos = 1 + 4·Im S` (conventions,
     `SIGN = -1`) is the whole job, and it is where the subtraction is already
     handled for us. MEEP is the primary anchor for this.
   - dolfinx has no LDOS path: it would mean driving with a line dipole and
     re-deriving the self-field subtraction inside a volume formulation. That
     is a second source of error, not a second anchor. Deferred, possibly
     indefinitely.

   Cross-sections ship first and completely; LDOS does not gate them.

## 5. Gates

Sequential; each is a stop.

1. **Circle vs Mie, in the external tool.** Each tool reproduces
   `reference/mie.py` to a stated tolerance, in both polarisations, before any
   star is run. Until this passes, a disagreement on the star is unattributable.
2. **External convergence study.** Resolution (MEEP) and mesh/element order
   (dolfinx) refined until the cross-section spectrum stops moving. The
   comparison tolerance is set by *this* floor — the external error dominates
   ours by orders of magnitude — and is measured, not assumed (non-negotiable
   §4).
3. **Null test.** Lossless material: absorption consistent with zero, stated
   per tool so that it can actually fail. Under MEEP it is `C_abs` itself — a
   flux tally that knows nothing about the material, so a non-zero reading is
   real evidence of a defect. Under dolfinx it is **not**: `C_abs` is a volume
   integral carrying `Im(ε)`, which is identically zero for a real material, so
   it returns exact zero by construction and cannot fail. The dolfinx null test
   is therefore the **optical-theorem residual** `(C_ext − C_sca − C_abs)/C_ext`
   — two volume integrals against one independent flux integral — held at the
   level of gate 2's floor.
4. **The star.** One Gielis shape, broad resonance under MEEP, sharp
   resonances under dolfinx, plus the shared overlap band. The shape is the
   README star — `rad = 200 nm`, `m = 6`, `n1 = 6`, `n2 = n3 = 12`,
   `n_core = 2.0` — so the figure a visitor sees and the geometry that carries
   the claim are one shape. `validation/gielis.py` owns it, and the drivers
   read a committed contour rather than importing pysie2d.

   **The incidence convention is not part of this gate, and cannot be.** Both
   drivers pin the incident wave to `angle = 0`, travelling along −z. The plan
   was to falsify that on the star, since a circle cannot see it. Neither can
   the star, and neither can a deliberately asymmetric Gielis shape: reversing
   the incidence moves `C_ext` by 3e-13 in dolfinx and 2.5e-05 in MEEP — its
   own noise — on *both*. The cause is reciprocity, not geometry. The forward
   scattering amplitude for `k̂` equals the one for `−k̂` for any reciprocal
   scatterer, so `C_ext` is direction-invariant whatever the shape, and
   losslessness carries `C_sca` with it.

   Two consequences, and they point opposite ways. A wrong pin **cannot**
   corrupt any cross-section this milestone freezes — the trap is not live
   here. But it would corrupt a direction-sensitive observable, which is the
   near field, the LDOS and the differential pattern, i.e. most of what comes
   after v1.0. So the convention is checked against the one observable that
   can fail: MEEP's far-field **pattern**, on the asymmetric shape, by
   `validation/direction_check.py`.
5. **Freeze.** External spectra written to a data file in the repo.
6. **MEEP's systematic, localised at the production resolution.** Gate 2 ran
   the `pml`, `box` and `decay` isolation groups at resolution 25, where grid
   error dominates them roughly tenfold; they therefore bound those
   systematics *at resolution 25* and say nothing about what limits resolution
   50, where the observed convergence order has fallen to 1.0 and the lossless
   `C_abs` null reading ticks back *up*. Re-running the three groups at
   resolution 50 is the honest completion of gate 2. It is deferred past the
   freeze deliberately, not dropped: until it runs, MEEP's tolerance is
   documented as *a bounded systematic we did not eliminate*, never as a
   converged floor. Whatever the re-run finds is recorded as found — if the
   systematic stays unlocalised, that wording stands permanently.

### Gate 4, as measured

Run 2026-09-23, after `39b9e9d` replaced the star's control-point spline with
an interpolating one. Every figure below is the worst pointwise `|Δ|` over the
grid, normalised by peak `C_ext` — study.py's normalisation, so these sit in
one table with the ladder's floors.

The plateau is gone. Under `addBSpline` the disagreement with pysie2d was flat
at 1.7e-04 across all four levels while dolfinx's own error fell 130×; that
was a 0.052 nm boundary displacement, not physics. It now falls monotonically:

| level | `C_ext` TE | `C_ext` TM | dolfinx's own residual |
|---|---|---|---|
| L1 (12, 40) | 1.89e-05 | 4.11e-05 | 2.37e-04 |
| L2 (8, 25)  | 4.39e-06 | 8.27e-06 | 3.70e-05 |
| L3 (6, 18)  | 1.43e-06 | 2.85e-06 | 9.25e-06 |
| L4 (4, 12)  | **2.68e-07** | **5.61e-07** | 1.86e-06 |

L4 is 638× better than the old plateau, and nothing has flattened: the ladder
is still falling at its finest level, so this is a measured bound on dolfinx's
error and not a floor. The production spectra on the full 51-point grid agree:
3.11e-07 (TE) and 5.69e-07 (TM), slightly above the 13-point figures because
the worst case is taken over four times as many points.

For scale, the same comparison on the circle at L4 reads 3.53e-08 (TE) and
3.07e-08 (TM) — the star costs an order, which is what six near-cusps cost a
mesher.

MEEP's star, at its production resolution 32, is bounded and not converged:
1.98e-02 (TE) and 4.34e-03 (TM) on the full grid, against 2.66e-04 and 1.53e-04
for its own circle at resolution 50. It is documented with gate 6's wording —
*a bounded systematic we did not eliminate* — and dolfinx carries the sharp
claim. ~1.7 significant figures of genuinely independent agreement is what it
contributes, and that is worth having from a method that shares nothing with
either of the others.

**What limits MEEP on the star is now named rather than described.** Its 40×
gap against its own circle was two confounded causes — six near-cusps on a Yee
grid, and `n_core = 2.0` against the circle's 1.5. One run at `--n-core 1.5`,
same resolution and same grid, separates them:

| run at resolution 32 | vs pysie2d, `C_ext` TE |
|---|---|
| star, `n_core = 2.0` | 1.75e-02 |
| star, `n_core = 1.5` | 4.16e-03 |
| circle, `n_core = 1.5` | 4.34e-04 |

The cusps cost 9.6× and the index contrast 4.2×, and their product is the 40×
that was observed. **The cusps dominate, but the contrast is not a rounding
detail** — a factor of four is most of an order, and it is the part that would
have been silently attributed to the geometry. Neither is a defect: subpixel
averaging cannot rescue a near-cusp, and a shorter interior wavelength is
resolved worse at fixed grid spacing. Both are why MEEP's star tolerance is
written as a bounded systematic.

### The reference these numbers are differenced against

pysie2d at `n_pts = 800`, measured against itself rather than assumed
(non-negotiable §4). On this star, worst pointwise `|Δ|` against `n_pts = 800`:

| `n_pts` | `C_ext` TE | `C_ext` TM |
|---|---|---|
| 100 | 3.39e-03 | 7.95e-04 |
| 200 | 4.85e-05 | 1.21e-05 |
| 400 | 5.39e-09 | 1.03e-09 |

So the reference contributes ~5e-09 to a comparison whose smallest entry is
2.7e-07 — two orders below the thing being measured, which is the condition for
the comparison to be about the external tool at all. **`n_pts = 200` is not
enough on this star**, though it is ample on the circle; a frozen star file must
carry `n_pts` ≥ 400 in its geometry block or the repo-side test measures
pysie2d's own discretisation and attributes it to dolfinx.

`validation/compare.py` runs these. It reads the material from the result
file's own record rather than being told, because a comparison that can be told
what was simulated can be told wrong: a star run at `n_core = 1.5` differenced
against pysie2d at 2.0 produces a plausible, meaningless number.

### Two records these numbers depend on

**`n_core` is now in both drivers' `knobs`.** It is the one physical input
`--n-core` overrides and whose default depends on the shape, so without it a
run at the star's 2.0 and one at the circle's 1.5 left byte-identical records.
Only one file in the study ever used the override — the resolution-32 star at
`n_core = 1.5` that separates the cusp from the contrast — and it was re-run to
carry its own record. Every other file's index follows from the shape through a
driver default that is in git, so re-running four hours of simulation to restate
what version control already says was not worth it.

**MEEP's `.npz` holds cross-sections in units of `a = 100 nm`, not nm.**
`freeze()` and the driver's progress print both multiply by `NM_PER_A`;
`np.savez` writes the raw arrays. `study.py`'s null-test report labelled them
`nm` and did not, so every MEEP `C_abs` null it printed was a hundred times
smaller than the quantity it named — the resolution-32 star null is 1.63e-01 nm,
not the 1.63e-03 that was on screen. Nothing downstream was wrong (the
handoff-2 tables were computed in nm and are correct, and every drift is a
ratio in which the unit cancels), but a number on screen with the wrong unit
beside it is one transcription away from being quoted. Both `study.py` and
`compare.py` now convert.

## 6. Packaging and transparency

Two goals that pull in opposite directions, and the resolution matters enough
to state plainly.

**Goal A — ignorable.** A user who clones the repo, runs `uv sync --frozen` and
runs the tests must never install, build or configure MEEP or dolfinx, and must
not see a failure or a skip that looks like a defect. Both are conda-first and
awkward under uv; neither belongs in `[project].dependencies` or in any extras
group this repo's lockfile resolves.

**Goal B — transparent.** "We validated it externally" is worth nothing if the
comparison is a number in a docstring. A reader must be able to see *what* was
compared, *against what*, *how closely*, and — if they care enough — re-run the
external side themselves and get the same answer.

These are not in conflict once the two audiences are separated: the external
run is a **maintainer** operation, and its *evidence* is a **reader** artefact.

### The three layers

**1. Frozen reference data — committed, human-readable, self-describing.**

Each external run writes a data file carrying not just the spectrum but
everything needed to reproduce it: geometry parameters, material, polarisation,
wavelength grid, the external tool and its version, the converged discretisation
settings, and the convergence evidence from gate 2 (what was refined, and by how
much the answer stopped moving). A reader opening one file learns the whole
provenance of that comparison without running anything.

**2. The regeneration scripts — committed, runnable, not installed.**

The MEEP and dolfinx drivers live in the repo, are readable as the
specification of what was actually simulated, and run only in an environment the
user builds themselves. They are the answer to "how do I check this myself?" and
they are what makes the frozen data falsifiable rather than asserted.

Alongside them: **an environment recipe** — explicit, versioned, and honest
about being conda-based. Not a `pyproject` extras group pretending uv can
resolve it, but a documented setup a reader can follow in an afternoon. That
recipe is part of the deliverable, not an afterthought.

**3. The repo's own test — runs for everyone, no extra environment.**

pysie2d is asserted against the frozen data using numpy only. It runs in CI for
every user, and it fails if pysie2d changes. This is where the validation has
teeth: the external tools' role is to *produce* the reference once, not to be
present at every test run.

### The validation guide

A user-facing document — the reader entry point, not a design doc — that states
for each anchor: what claim it supports, what was compared, the agreement
actually achieved with its number, and where that number's tolerance comes from
(non-negotiable §4). It covers the whole validation story, the existing Mie and
analytic-limit anchors included, not only the new external ones, so that
"how is this package validated?" has exactly one place to be answered.

It ends with the reproduction path: build this environment, run this script,
compare against this committed file, expect this agreement. A cold visitor who
follows it reaches the same numbers — which is the actual definition of
transparency here, and the only version of it worth the work.

The README points at this guide from the validation section, and the figures
that come out of the comparison (spectrum overlays, one per anchor and
polarisation) are what a visitor sees before reading any of it.

### What this deliberately does not do

- No `[project.optional-dependencies]` entry for MEEP or dolfinx. An extras
  group that most readers cannot install produces a skipped test that looks
  like a defect, and forces the lockfile to carry a resolution CI never uses.
- No CI job running the external tools. Their convergence runs are slow, their
  environments are fragile, and a red build caused by an upstream conda
  packaging change teaches nobody anything about pysie2d.
- No auto-regeneration of the frozen data. It is regenerated deliberately, by a
  maintainer, when the physics being compared changes — and the diff of that
  file is then itself reviewable evidence.

Exact file layout (`tests/data/`, `validation/`, or `docs/design/studies/`) and
the data file format are code-spec decisions, not settled here.

## 7. Out of scope for v1.0

- QNM eigenvalues for non-circular shapes, and any fit of an external spectrum
  to λ and Q.
- LDOS under dolfinx.
- Dispersive materials.
- Multiple particles, substrates, or anything the package does not already do.
