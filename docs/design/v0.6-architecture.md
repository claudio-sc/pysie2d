## 1. What v0.6 is

The solver converges at **exactly first order in `nn`** on a perfect circle
with perfectly uniform nodes, where node placement cannot be a factor (handoff
§5.1). The cause is the quadrature treatment of the logarithmic Green-function
singularity: the shipped Maradudin scheme patches the diagonal entry only, and
the O(h) error is spread across the near-diagonal neighbourhood, not localised
where the patch is.

Replacing it with Kress–Martensen product quadrature, and supplying analytic
second derivatives of the boundary parametrisation, takes the circle from
1.4e-2 at `nn = 30` to **3.4e-15 at `nn = 30`** against analytic Mie (handoff
§5.3).

v0.6 is that change, plus everything it drags in:

| # | Capability | Why it is in v0.6 and not later |
|---|---|---|
| 1 | Kress–Martensen splitting on all four blocks | The change itself. **Specified** in [kress-spec.md](kress-spec.md). |
| 2 | Analytic `ddf` / `ddg` (closed-form `d²r/dθ²`) | **Landed** (`geometry._rderiv2`). Without it the rate caps at 3 (handoff §6.4) — that cap does not yet apply, since Kress itself (item 1) isn't ported. |
| 3 | Smooth parametrisation `w(t)` replacing the `np.interp` arc-length inversion | **Landed** (`Parametrisation`, G1 passed). Kress needs equispaced nodes in the quadrature parameter; a C⁰ map destroys the accuracy being bought. See §3. |
| 4 | Curvature-adaptive node density | **Held pending G3 — see §4.1.** Measured twice as a net *loss* on smooth shapes; kept in scope, and G3's near-corner numbers decide whether it ships or moves to v0.7. |
| 5 | Far-field angular quadrature | **Closed by G5, no code change.** The ~1e-4 `Q_sca` floor (handoff §3) was the closing-angle double count `dc9da93` fixed; the periodic trapezoid is spectral and `Q_sca` matches Mie at round-off from `n_angles = 17` (study plan, G5). |
| 6 | `assemble_matrix_dwn`, QNM and sensitivity plumbing | Parity with `assemble_matrix` is bit-for-bit and guarded; both change together (handoff §7.3). |
| 7 | The `theta=` API break | See §5. |
| 8 | README, figures and docs regenerated | The headline claim changes from first order to spectral. Lands last (§8). |

**Non-goals, explicitly.** True geometric corners (§6). Resolving the
uniform-arc-length star anomaly of handoff §9 — untouched by decision, and the
study's reference is chosen to route around it (study plan §3). Retaining the
Maradudin path as a second in-repo anchor: deleted, Mie is the anchor, and
v0.5 remains on PyPI for anyone who wants the old scheme.

## 2. The mechanism, in one page

The periodic trapezoid rule is spectrally accurate on smooth periodic
integrands and loses that property entirely to a logarithmic singularity.
Kress splits the kernel so that everything *sampled* is analytic and the
singular factor — universal, the same for every geometry, wavelength and
material — is integrated exactly against a trigonometric interpolant:

    K(t, τ) = K₁(t, τ) · ln( 4 sin²((t − τ)/2) ) + K₂(t, τ)

`∫K₂φ` goes to the trapezoid rule; `∫K₁·ln(...)·φ` goes to closed-form weights
`R_j`, which are **circulant** (N distinct values, not N²), **independent of
geometry, wavelength, material and index**, and therefore computable once per
`nn` and cached for the life of the process. That last property is what makes
this cheap for QNM work, where `M(λ)` is reassembled `4 · n_quad_per_side`
times per contour.

The splittings, diagonal limits and reference implementation for this
package's specific normalisation — in which `chi` carries the Jacobian, so no
explicit `|x'(τ)|` appears in the kernel — are handoff §6.1–6.3 and §10. They
are not restated here; the code-specs will quote them verbatim.

## 3. Nodes, the parametrisation object, and why arc length goes away

### 3.1 The constraint, stated exactly

Kress's weights come from trigonometric interpolation, so the nodes must be
equispaced **in the quadrature parameter** — *not* necessarily in θ, and not in
arc length. This is the one real constraint the scheme imposes.

Uniform arc length is therefore **not** a dealbreaker. Write the boundary as
`θ = w(t)` with `t` equispaced, integrate in `t`, and the Jacobian `w'(t)` is
absorbed exactly the way `γ = |x'(θ)|` already is. Near-diagonal behaviour
stays `r ≈ |dx/dt|·|t − t'|`, so `4 sin²((t − t')/2)` remains the correct
periodic stand-in and every diagonal limit carries over with `γ` replaced by
`|dx/dt| = γ(w(t))·w'(t)`.

**What *is* the dealbreaker is smoothness.** `_uniform_arc_theta` inverts arc
length with `np.interp` — piecewise linear, so `w` is only C⁰. A C⁰ change of
variables destroys precisely the smoothness the trapezoid rule's spectral
accuracy rests on. Kress on the shipped arc-length path would degrade to low
order on every non-circular shape, silently.

This is the same object handoff §9 flags as suspicious. A smooth `w` is a
**prerequisite** for Kress on graded shapes regardless of whether it also
happens to explain §9; the study does not chase §9 and does not claim to.

### 3.2 One object, three densities

Uniform θ, uniform arc length and curvature-adaptive grading are not three code
paths. They are one map `w(t)`, `t` equispaced, defined by a target density

    |dx/dt| = ρ(t)

- uniform θ → `w = identity`
- uniform arc length → `ρ = const`
- adaptive → `ρ` curvature-driven, bounded (§4)

So v0.6 introduces a **`Parametrisation`** object: a smooth 2π-periodic
monotone map `w` together with `w'` and `w''`, built once from a density, then
immutable and reusable. Node placement becomes a choice of density; the
quadrature knows nothing about how `w` was built and only requires that `t` be
equispaced.

`arc_length: bool` is **removed** from the public API. It collapses into the
const density, and keeping it as an alias would preserve a name that no longer
describes a distinct mechanism.

**The default map is uniform θ, not uniform arc length** (decided 13 Sep 2026,
kress-spec D1). Under Kress uniform θ is the most accurate map once resolved on
every shape measured, including spiky stars, and at low resolution no other
map is reliably better: on spiky stars at `nn` 50–300 uniform θ reaches 1e-3
first where any map does (conventions §13; study plan, "Spiky stars at
campaign resolution", 14 Sep 2026).

*Note for the downstream project:* `gielis-oed` asserts `arc_length=True` on
every catalogue geometry (D13), because `arc_length=False` makes `_etoil` force
`a = b = 1` and both `∂M/∂a` and `∂M/∂b` become identically zero with nothing
raised. Under `Parametrisation` that failure mode does not exist — there is no
setting that silently discards `a` and `b`.

### 3.3 The three invariants

These are the rules that, if broken, produce a plausible wrong answer rather
than an error. They are recorded as **`docs/conventions.md` §13**, tentatively,
and will be fixed or amended by the study before the migration closes.

1. **Nodes are equispaced in `t`.** Not in θ, not in arc length. Violating it
   drops the quadrature from spectral to first order with nothing raised.
2. **`w` is independent of λ.** If the parametrisation varies with λ, `M(λ)`
   loses holomorphy and Beyn's contour integral silently returns wrong modes.
   This is the same argument that kills condition-number-optimal node placement
   (handoff §4.5): the smallest singular value of a matrix is not analytic in
   λ, and a QNM is by definition a λ where `M` is singular.
3. **`w` is independent of any parameter being differentiated.** Otherwise
   `M(p₀ ± h)` re-places nodes between the two evaluations and reintroduces the
   O(h) term that freezing removes — measured rate on `∂M/∂b`: 2.7 without
   freezing, 100.1 with (conventions §10).

Invariants 2 and 3 are what the frozen-map API of §5 exists to make
structurally unreachable.

## 4. The adaptive density

**User-facing specification.** A range of wavelength-to-arc-length ratios
`[R_min, R_max]`, in the units conventions §12 already pins (`R =
wavelength_over_ds`, D17 — rungs are placed in `R`, never in raw `n_pts`,
because 200 points reads as `R = 37.1` on a circle and 17.5 on an aspect-3
ellipse). The **upper** bound — finest sampling — applies at the
highest-curvature inflection points; the **lower** bound applies along the
longest, smoothest sections.

**Why it is well-motivated rather than speculative.** Gielis shapes approach
true corners in a limit (§6), and at large exponents curvature concentrates
into a boundary layer whose width narrows with the exponent. The boundary stays
analytic, but the analyticity strip thins. That is exactly the regime graded
spectral quadrature is for, and the `R` bounds are a direct request to resolve
that layer.

### 4.1 The measured case against it, as of 12 Sep 2026

Two ladders have now asked whether grading pays, and **both said no on smooth
shapes** (study plan, the two ladder sections):

- On the **shipped** first-order scheme it cannot pay in principle: the error is
  set by the worst-resolved node, so grading at fixed `nn` strictly increases
  `max Δs`. Measured 1.4–1.6× worse, matching the worst-node resolution ratio
  to within 4 %.
- Under the **Kress prototype** it fails again on ellipses, for a different
  reason: composing with `w` narrows the analyticity strip of `f∘w` and delays
  the spectral onset — up to 5800× pre-asymptotically — before buying a
  constant once both schemes converge.

Neither result touches the regime grading exists for. These are ellipses, of
curvature contrast ~3 against the ~8.8e3 of a sharp star, and the near-corner
boundary layer §4 invokes is exactly what **G3** measures. So the honest
position is that **item 4 is justified by G3 or it is deferred** — the case for
it cannot be made on smooth shapes, and has twice failed to be.

**Decided 12 Sep 2026: held pending G3**, which is the next gate to run. G3 was
already scheduled for the validity envelope, so this adds no work — it adds a
second thing the same measurement decides. If the near-corner numbers do not
support grading, item 4 moves to v0.7 and the release is Kress plus the smooth
parametrisation, which are validated on their own.

Everything below stands as the specification *if* item 4 is kept.

**The traps, all of one kind — a kink anywhere in the chain costs the spectral
accuracy being paid for:**

- **The clamp must be smooth.** `np.clip(ρ, lo, hi)` is C⁰: two kinks per lobe,
  and the result is the `np.interp` failure again, silently. Requires a smooth
  saturation — softmin/softmax, or a Fourier low-pass of `ρ`. The same applies
  to curvature itself, which is sharply peaked on high-exponent shapes.

  **Corrected by G2 (partial), 12 Sep 2026** — two claims in the paragraph above
  as first written were wrong, and the corrections are measured:

  - **The low-pass bandwidth must not be tied to `nn`.** A bandwidth ∝ `nn`
    makes `w` a *different map at every resolution*, so refinement chases a
    moving target and `∫w' dt` stalls near 1e-3 instead of converging. It is
    invariant 3.3.3 wearing a different hat. Bandwidth is a property of the
    *shape*, and G2 identifies which one: the **angular width of the curvature
    layer**, the fraction of the boundary where `ln|κ|` sits within 1 of its
    maximum. It narrows as the exponent rises and is the geometric signature of
    the thinning analyticity strip — measurable before any solve. The `nn`
    coupling survives only as the check `nn ≥ 4M`.
  - **Smooth with a positive kernel, not a sharp cutoff.** Truncation
    Gibbs-undershoots the peaked log-curvature and digs a narrow artificial
    minimum; since `min σ = 1` is what pins `nn`, the band then gets set by the
    undershoot — measured, every node landed at `R ≈ 28.7` for a requested
    15–30. A Gaussian taper cannot leave the range of its input.

  A third G2 finding reframes the clamp itself: with the exponent `α` **derived
  from the band** rather than pinned, the clamp is never active and hard and
  smooth are indistinguishable. The trap is real but reachable only by pinning
  `α`, so smooth saturation stays in as a guard, not as the normal path.
- **λ in the density.** The `R` specification puts λ in `ρ`, which collides
  head-on with invariant 3.2. Resolved by making the reference wavelength a
  property of the `Parametrisation`, fixed at construction, **default 1550 nm**
  — so the density is a design-time input, not a per-solve one, and a contour
  sweep cannot move the nodes.
- **Scale covariance.** An `R` ratio is dimensionless, so conventions §9
  survives — provided nothing in the density evaluation introduces an absolute
  length. `n_fine` in the inversion remains the thing to watch, exactly as §9
  already warns.

## 5. The API break

### 5.1 What breaks and why it must

v0.5 made `theta` a required keyword field on `Geometry.__init__` and added it
to `Geometry.gielis`; it is the frozen-node path of conventions §10.

Under Kress, `θ_j = w(2πj/nn)`, so the θ *array* still identifies where the
nodes are — but assembly now also needs `w'` and `w''` at those points, and
**those cannot be recovered from the array**. A caller who passes a bare θ
array in v0.6 would get a plausible wrong answer. That is precisely the failure
mode the parameter was created to prevent.

So `theta=` becomes a `Parametrisation` object rather than an `ndarray`.
Freezing the *map* — not the angles — preserves both the quadrature and the §10
guarantee, and makes invariants 3.3.2 and 3.3.3 structurally unreachable rather
than merely documented.

### 5.2 How it is carried

Per the downstream project's break protocol, all four of:

1. argued before it is written — this document;
2. a `BREAKING CHANGE:` footer, so semantic-release records it in
   `CHANGELOG.md`; the parser sees nothing without the footer;
3. `README.md` shows old call → new call, so a user migrates without reading a
   diff;
4. justified to **users**, not to us: the old signature would return a
   plausible wrong answer under the new quadrature.

*Precedent to not repeat:* `247492d` shipped the v0.5 `theta` addition as a
plain `feat:` with no footer, so anyone constructing `Geometry` directly from
external arrays — which the class docstring explicitly invites — broke on
upgrade with nothing in the changelog to explain it.

### 5.3 Downstream

`gielis-oed` pins `pysie2d>=0.5,<0.6`, so v0.6 cannot reach it accidentally;
migration is deliberate. Its frozen-node traffic funnels through one choke
point, `Shape.geometry(n_pts, theta=...)` in `catalogue.py`, with three
consumers: `continuation.py`, `observable.py`, `angular.py`.

**That migration is out of scope for v0.6 and gets no code-spec here.** Two
notes for whoever does it:

- **D12 is relaxed, not broken.** It forbids second derivatives on the grounds
  that "arc-length node placement goes through `np.interp` and is only
  piecewise-smooth". A smooth `w` removes the stated cause.
- **D6/D6a survives unchanged.** Curvature `|f'g'' − g'f''| / (f'² + g'²)^{3/2}`
  is parametrisation-invariant, so re-expressing `df, dg, ddf, ddg` with
  respect to `t` leaves `|κ|` and the neck-width rejection sampling untouched —
  provided all four are consistently in the same parameter.

## 6. Non-goal: true geometric corners

The Gielis family does reach true corners in a limit. For `m = 4, a = b = 1,
n1 = n2 = n3 = n`:

    r = (|cos θ|ⁿ + |sin θ|ⁿ)^(−1/n)  →  1 / max(|cos θ|, |sin θ|)   as n → ∞

which is a square, with four right-angle corners.

**At any finite exponent the boundary is still analytic**, and that is the
regime v0.6 addresses: curvature concentrates into a narrowing boundary layer,
which graded Kress resolves. True corners are a different problem — the
boundary operator loses compactness, the second-kind theory changes, and
corner-specific algebraic grading (Kress's sigmoid substitution) is needed
alongside a singularity-aware splitting. Out of scope, and recorded here so
nobody discovers it mid-migration.

What v0.6 *does* owe is the boundary between the two: **how far into the
near-corner regime graded Kress holds up, and where it breaks.** That is a
measurable curve — error versus exponent at fixed `nn` — and it defines the
honest validity envelope of the release. It also gives `gielis-oed`'s curvature
rejection sampling (D6) a number to point at instead of a judgement call.

## 7. Consequences to expect

- **Two anchors in `tests/` are too coarse to survive the migration**, measured
  12 Sep 2026. The QNM pole constants are quoted to five decimals, which reads
  as a fixed **1.259e-6 nm** error — invisible against the shipped 0.38 nm and
  dominant under Kress; regenerate them from `qnm_denominator` with more
  digits. And `n_quad_per_side = 6` pins the Beyn contour at ~5e-6, so
  `test_qnm.py`'s justification for it ("identical modes to 1e-8 against a
  0.38 nm discretisation error") is a statement about the *shipped* error and
  does not carry over.
- **Tolerances across `tests/` will be enormously slack.** Every one carries a
  justification (CLAUDE.md non-negotiable 4), and every justification that
  cites a first-order rate becomes false. Re-anchoring the suite is a
  first-class part of the migration, not cleanup.
- **`richardson_limit` may become unnecessary.** Conventions §12 exists because
  `J` converges at first order; if it no longer does, the extrapolation
  machinery is solving a problem that is gone. Conventions §12 is then
  historical and must say so.
- **The self-Green anchor runs at `nn = 1000` for 1 %.** It is the strongest
  near-field anchor in the suite and the best evidence the splitting is right
  near the boundary. Expect it to become cheap.
- **Default `n_pts` is 200.** If the circle reaches machine precision at 30,
  the default wastes an O(nn³) factor on every user call — but lowering it is a
  second, silent behavioural break on top of the API one. **Decision deferred**
  to the point in the migration where the numbers exist.
- **Assembly gains, the solve collapses.** One extra Bessel array per block,
  one `O(nn²)` log array per geometry (λ-independent, reusable), one cached
  circulant `R`. Against that, `nn` drops by an order of magnitude and the
  `O(nn³)` solve falls by three. Net strongly positive (handoff §7.2).

## 8. Sequencing

1. **Study** — [studies/quadrature-study-plan.md](studies/quadrature-study-plan.md).
   Quantifies every convergence gain, proves the tooling works, and ends by
   producing the code-specs.
2. **Code-specs** — written from the study's working, refined scripts. Coarse
   granularity by capability, not per-commit. They target a worker who cannot
   derive the physics: exact signatures, formulae verbatim, the test that
   proves each piece, each tolerance *with its justification already written*,
   and the explicit "do not do X" traps. They cite conventions §13 by number
   rather than re-arguing holomorphy.
3. **Migration** — production code, in spec order.
4. **Docs, README and the three `examples/` figures — last.** They can only be
   truthful after the migration. Interim findings are published to the study's
   running artifact as they land (study plan §5), not to the README.
5. **CI** — managed towards the end of the migration.

The merge to `main` is a release decision and is asked, not taken: v0.6 is a
roadmap milestone and ships to PyPI on merge.
